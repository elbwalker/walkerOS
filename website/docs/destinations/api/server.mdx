# Server API Destination

<PackageLink
  env="server"
  github="packages/server/destinations/api"
  npm="@walkeros/server-destination-api"
/>

The server API destination sends events from Node.js to any HTTP(S) endpoint
using `fetch`. It supports configurable timeouts (default 5000ms), custom transforms, and dependency injection for testing.

## Usage

### Basic usage

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/server-destination-api';

await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        settings: {
          url: 'https://api.example.com/events',
        },
      },
    },
  },
});`}
  language="typescript"
/>

### With headers and timeout

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/server-destination-api';

await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        settings: {
          url: 'https://api.example.com/events',
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            Authorization: 'Bearer your-token',
          },
          timeout: 5000,
        },
      },
    },
  },
});`}
  language="typescript"
/>

A request that fails, times out or gets an error status is reported as a failed
push: the event reaches the dead-letter queue and the collector logs one ERROR
line per cause and minute with the HTTP status. A `429` and a `5xx` answer are
retryable, other `4xx` answers are not. Without `settings.url` the destination
fails to start with a `config` error.

### With custom transform

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/server-destination-api';

await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        settings: {
          url: 'https://api.example.com/events',
          // data is the mapped data, or the event without a mapping
          transform: (data) =>
            JSON.stringify({ sent_at: Date.now(), payload: data }),
        },
      },
    },
  },
});`}
  language="typescript"
/>

### With batching

Set `config.batch` to send events in one request per flush instead of one
request per event. The options are in
[Batch scheduling](/docs/mapping/rule#batch-scheduling).

Each flush is a single request whose body is a JSON array, one element per
event. Mapping still applies per event, so an element is the event's mapped
data when a rule produced some and the raw event otherwise. A `transform` runs
per element, not once for the whole array, and its return value becomes the
element as is: a transform that returns a JSON string, like the one above,
adds that string to the array, not the object it encodes.

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/server-destination-api';

await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        batch: { wait: 1000, size: 100 },
        settings: {
          url: 'https://api.example.com/events',
        },
      },
    },
  },
});`}
  language="typescript"
/>
