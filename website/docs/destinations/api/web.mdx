## Usage

### Basic usage

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/web-destination-api';

const { collector, elb } = await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        settings: {
          url: 'https://api.example.com/events',
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            Authorization: 'Bearer your-token',
          },
        },
      },
    },
  },
});`}
  language="typescript"
/>

### Advanced usage with transform

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/web-destination-api';

const { collector, elb } = await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        settings: {
          url: 'https://api.example.com/events',
          transport: 'fetch',
          // data is the mapped data, or the event without a mapping
          transform: (data) =>
            JSON.stringify({ sent_at: Date.now(), payload: data }),
        },
      },
    },
  },
});`}
  language="typescript"
/>

### With batching

Set `config.batch` to send events in one request per flush instead of one
request per event. The options are in
[Batch scheduling](/docs/mapping/rule#batch-scheduling).

Each flush is a single request whose body is a JSON array, one element per
event. Mapping still applies per event, so an element is the event's mapped
data when a rule produced some and the raw event otherwise. A `transform` runs
per element, not once for the whole array. Batched requests carry no
`traceparent` header: a batch can aggregate events from distinct traces, so
there is no single identity to stamp.

Set `size` explicitly and keep it small: the `fetch` and `beacon` transports
send with `keepalive`, and browsers reject a `keepalive` request once the bodies
in flight exceed 64 KiB, while the default `size` is 1000 events. Such a flush
fails without being reported (see [Transport methods](#transport-methods)). A
full event is around 0.5 to 1 KiB.

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationAPI } from '@walkeros/web-destination-api';

const { collector, elb } = await startFlow({
  destinations: {
    api: {
      code: destinationAPI,
      config: {
        batch: { wait: 1000, size: 25 },
        settings: {
          url: 'https://api.example.com/events',
        },
      },
    },
  },
});`}
  language="typescript"
/>

## Transport methods

- **fetch** (default): `fetch` with `keepalive`, so the browser completes the
  request even when the page unloads first
- **xhr**: a synchronous `XMLHttpRequest`
- **beacon**: `navigator.sendBeacon()`, always a `POST` without the configured
  `headers`

The destination ignores the response: a failed request (an error
status or a network error) is not reported, the event counts as delivered and
does not reach the dead-letter queue.
