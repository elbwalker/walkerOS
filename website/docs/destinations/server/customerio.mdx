# Customer.io

<PackageLink env="server" github="packages/server/destinations/customerio" npm="@walkeros/server-destination-customerio" status="beta" />

Server-side event delivery to [Customer.io](https://customer.io/) via the official [`customerio-node`](https://www.npmjs.com/package/customerio-node) SDK. Tracks events with `TrackClient.track()`, manages identities with `identify()`, and supports the customer lifecycle: page views, device registration, suppress/unsuppress and profile merging. Transactional messaging via `APIClient.sendEmail()` / `sendPush()` does not deliver today (see [Transactional messaging](#transactional-messaging)).

## Identity

Identity is resolved automatically from each event: `customerId` defaults to `user.id` and `anonymousId` defaults to `user.session`. Customer.io requires a `customerId` or `anonymousId` per event. When `customerId` is missing, the destination automatically falls back to `trackAnonymous()` so anonymous visitor data is preserved.

## Customer lifecycle

Per-rule mapping settings control which lifecycle methods are called in addition to the default `track()`:

| Mapping Setting | SDK Call                  | Use For                         |
| --------------- | ------------------------- | ------------------------------- |
| `identify`      | `identify()`              | Login, signup, profile updates  |
| `page`          | `trackPageView()`         | Page views (only the `url` is sent) |
| `destroy`       | `destroy()`               | Delete a person (the id can be re-added) |
| `suppress`      | `suppress()`              | Suppress a person (unlike `destroy`, the id cannot be re-added) |
| `unsuppress`    | `unsuppress()`            | Undo `suppress`                 |
| `addDevice`     | `addDevice()`             | Register push notification token|
| `deleteDevice`  | `deleteDevice()`          | Remove push token               |
| `merge`         | `mergeCustomers()`        | Consolidate duplicate profiles  |

Use `silent: true` on the rule to fire only the lifecycle call without tracking a second `track()` event.

Every lifecycle call needs a resolved `customerId`. `addDevice` and `deleteDevice` also need `deviceId` and `platform`, and `merge` needs all four of its fields. When a value is missing, the destination skips the call without an error. If the rule also sets `silent: true`, nothing is sent and the push still counts as delivered, as with a `page` rule on an anonymous visitor's page view.

## Transactional messaging

Set `settings.appApiKey` to call `sendEmail` / `sendPush` via Customer.io's App API from a mapping rule. These calls do not deliver today. The SDK accepts only its own `SendEmailRequest` and `SendPushRequest` objects, so every call fails with `transport`, logged at ERROR, and nothing is sent. Without `appApiKey`, a `sendEmail` or `sendPush` rule skips the call without an error.
