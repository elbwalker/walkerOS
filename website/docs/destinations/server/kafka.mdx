# Apache Kafka

<PackageLink env="server" github="packages/server/destinations/kafka" npm="@walkeros/server-destination-kafka" status="beta" />

Server-side event streaming to [Apache Kafka](https://kafka.apache.org/) via the [`kafkajs`](https://kafka.js.org/) client. Each event is serialized as JSON, keyed for partition-friendly ordering, and produced to a configurable topic. It supports TLS and SASL authentication (PLAIN, SCRAM), gzip compression, per-rule topic and key overrides, and graceful shutdown via `destroy()`.

## Installation

<Quickstart data={data} />

<Configuration type="destination" data={data} />

The destination creates a single long-lived `kafkajs` producer and connects it at the first push, so a flow starts without a reachable broker. kafkajs retries a failed connect or send as `settings.kafka.retry` allows. When a send still fails, the event fails with a `transport` error, marked `retryable` unless no retry can fix it (such as `MESSAGE_TOO_LARGE`), and goes to the dead-letter queue ([when delivery fails](/docs/destinations#when-delivery-fails)). A topic that does not exist fails every event ([below](#runtime-error-when-the-topic-is-missing)). On flow hot-swap or server shutdown, `destroy()` calls `producer.disconnect()` to close the connections.

## Message format

Events are serialized as JSON and produced with the following structure:

- **topic**, from `settings.kafka.topic` (or `mapping.settings.topic` override)
- **key**, resolved from `settings.kafka.key` (or `mapping.settings.key` override) mapping path; defaults to the event name with spaces replaced by `_` (e.g. `page_view`, `order_complete`) for partition-based ordering. A key path whose value is not a non-empty string (a number, for example) falls back to that default
- **value**, the mapped `data` when a `data` mapping resolves to an object with at least one field, otherwise the full walkerOS event, `JSON.stringify()`-ed
- **headers**, `content-type: application/json` plus any static `settings.kafka.headers`
- **timestamp**, event timestamp as string (ms since epoch)

Use `mapping.settings.topic` to route specific events to dedicated topics (e.g. orders to `orders-stream`, identities to `identity-stream`). Use `mapping.settings.key` to set a key path per rule (e.g. `data.order_id` for order events).

`settings.kafka.compression` defaults to `gzip`, which kafkajs ships. `snappy`, `lz4` and `zstd` need a codec registered in kafkajs's `CompressionCodecs` in the same process. The destination registers none, so register the codec in your own code before the first send (integrated mode). Without one, every send fails with a `transport` error.

## Setup

:::caution No safe defaults
This destination's setup requires explicit `numPartitions` and `replicationFactor`.
There is no universally correct default for either: `replicationFactor` must be
less than or equal to broker count, and `numPartitions` is a function of
expected throughput and consumer parallelism. The boolean form `setup: true` is
rejected with an error listing the required fields. Only the object form is
valid.
:::

Provision a topic once per environment with the CLI:

<CodeSnippet
  code={`walkeros setup destination.kafka`}
  language="bash"
/>

The command prints `setup: ok destination.kafka`; with `--json` it prints a JSON
result with `{ topicCreated, schemaRegistered }`. The command is idempotent and
safe to re-run. Drift on `numPartitions`, `replicationFactor`, or
`configEntries` is logged as a `setup.drift` warning with the field, the
declared and the actual value, and never auto-mutates the broker.

`config.setup`:

- omitted or `false` (default): no provisioning; the command prints
  `setup: skipped destination.kafka (config.setup is unset)` (or `is false`).
- `true`: the command fails with an error that names the required fields.
  There are no safe defaults for partition count or replication factor.
- `{ numPartitions, replicationFactor, ... }`: object form is the only valid
  form. See the `Setup` interface in the package for full options.

### Required fields

| Field               | Type   | Notes                                                     |
| ------------------- | ------ | --------------------------------------------------------- |
| `numPartitions`     | number | Required at runtime. No safe default.                     |
| `replicationFactor` | number | Required at runtime. Must be `<= broker count`.           |

### Optional fields

| Field            | Type    | Notes                                                       |
| ---------------- | ------- | ----------------------------------------------------------- |
| `topic`          | string  | Falls back to `settings.kafka.topic` when omitted.          |
| `configEntries`  | object  | Topic-level config, e.g. `{ "retention.ms": "604800000" }`. |
| `schemaRegistry` | object  | Confluent Schema Registry binding (see below).              |
| `validateOnly`   | boolean | kafkajs broker-side dry-run. No topic is created.           |

### Example

<CodeSnippet
  code={`{
  "destinations": {
    "kafka": {
      "package": "@walkeros/server-destination-kafka",
      "config": {
        "settings": {
          "kafka": { "brokers": ["broker:9092"], "topic": "walkeros-events" }
        },
        "setup": {
          "numPartitions": 6,
          "replicationFactor": 3,
          "configEntries": { "retention.ms": "604800000" }
        }
      }
    }
  }
}`}
  language="json"
/>

### Schema Registry (optional)

<CodeSnippet
  code={`{
  "setup": {
    "numPartitions": 6,
    "replicationFactor": 3,
    "schemaRegistry": {
      "url": "https://schema-registry.example.com",
      "subject": "walkeros-events-value",
      "schemaType": "JSON",
      "schema": "{ \\"type\\": \\"object\\" }",
      "compatibility": "BACKWARD"
    }
  }
}`}
  language="json"
/>

The schema is registered via the Confluent Schema Registry REST API. The
optional `compatibility` level is set on the subject after registration.

### Runtime error when the topic is missing

When `setup` was not run and the topic does not exist on the cluster, every
event fails with `Kafka push failed`, a retryable `transport` error, once the
kafkajs retries are used up. kafkajs hands over the broker's
`UNKNOWN_TOPIC_OR_PARTITION` inside its retry error, so in the event's
dead-letter entry it is the cause of the error's cause. Run setup with explicit
`numPartitions` and `replicationFactor` to provision the topic.

## Authentication

### Confluent Cloud (SASL/PLAIN)

<CodeSnippet
  code={`{
  "kafka": {
    "brokers": ["pkc-xxxxx.us-east-1.aws.confluent.cloud:9092"],
    "topic": "walkeros-events",
    "ssl": true,
    "sasl": {
      "mechanism": "plain",
      "username": "$secret.CONFLUENT_API_KEY",
      "password": "$secret.CONFLUENT_API_SECRET"
    }
  }
}`}
  language="json"
/>

### SASL/SCRAM

<CodeSnippet
  code={`{
  "kafka": {
    "brokers": ["broker.example.com:9096"],
    "topic": "walkeros-events",
    "ssl": true,
    "sasl": {
      "mechanism": "scram-sha-512",
      "username": "$secret.KAFKA_USERNAME",
      "password": "$secret.KAFKA_PASSWORD"
    }
  }
}`}
  language="json"
/>

`mechanism: "aws"` is kafkajs's own AWS mechanism: it needs
`authorizationIdentity` next to `accessKeyId` and `secretAccessKey`, and a
broker that offers the `AWS` SASL mechanism. `oauthbearer` needs a token
provider function, which these settings cannot hold, so it does not
authenticate.
