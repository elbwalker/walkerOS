## Identity

Without `settings.identify` the track calls carry no `distinct_id`, so the quickstart's events are tied to no user. Map `distinctId` in `settings.identify`, for example to `user.id` as the examples above do, or per rule. People operations run only when a `distinctId` resolves.

## Consent and delivery

The quickstart sets no `config.consent`, so Mixpanel receives every event. Add `config.consent` to send only with consent ([consent management](/docs/guides/consent)).

Each event is sent at once. This destination has no `pushBatch`, so `config.batch` has no effect and the collector logs one ERROR line saying so ([batch scheduling](/docs/mapping/rule#batch-scheduling)). A request that fails or that Mixpanel rejects fails the event with the code `transport`.
