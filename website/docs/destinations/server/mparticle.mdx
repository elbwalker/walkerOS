# mParticle

<PackageLink env="server" github="packages/server/destinations/mparticle" npm="@walkeros/server-destination-mparticle" status="beta" />

Server-side event delivery to [mParticle](https://www.mparticle.com/) via the HTTP Events API. Each event is sent as its own batch, one POST per event, to the regional mParticle pod using HTTP Basic auth (`apiKey` / `apiSecret`). Supports user identities, user attributes, consent state, and environment targeting.

## Installation

<Quickstart data={data} />

The `apiKey` and `apiSecret` come from an mParticle **input feed** (Setup, Inputs, Feeds, Custom Feed). Requests go to `https://s2s.mparticle.com/v2/events` for the default pod `us1` and to `https://s2s.{pod}.mparticle.com/v2/events` for the other pods.

## Identities and attributes

- `userIdentities`: map walkerOS event fields to mParticle identity types (`customer_id`, `email`, `other`, etc.). Without it the batch carries no user identities.
- `userAttributes`: resolved from each event and placed on the batch's `user_attributes` object.
- `consent`: a fixed `consent_state` object, sent unchanged on every batch whatever the event's walkerOS consent says.
- `sourceRequestId`: defaults to `event.id` if unset; used by mParticle for deduplication.

Event properties reach mParticle as `custom_attributes` only through a mapping rule's `data` or `include`, or the destination's `config.data` or `config.include`. Without any of them, mParticle receives the event name, its timestamp and its id.

## Delivery failures

A non-2xx answer from mParticle fails the push with `transport` and that status, logged at ERROR; a 429 and a 5xx are retryable, other 4xx answers are not. A missing `apiKey` or `apiSecret` fails with `config`.
