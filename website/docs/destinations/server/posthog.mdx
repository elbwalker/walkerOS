## Identity

Without `settings.identify` the `distinctId` is the event's `user.id`, then `user.hash`, then `user.session`. An event without any of them is sent with the `distinctId` `anonymous`, so all such events share one distinct id.

## Batching and delivery

This destination batches by default: `config.batch` sends a batch at 20 events, 10 seconds after the last event, or 30 seconds after the first, whichever comes first, and each event keeps its own outcome. Set `config.batch: { size: 1 }` to send each event at once. How batching, retries, deduplication and acknowledgement work for the server SDK destinations is described in [Server SDK destinations](/docs/destinations#server-sdk-destinations).

## Consent

The quickstart sets no `config.consent`, so PostHog receives every event and a `walker consent` command changes nothing. Add `consent: { analytics: true }` to `config`, next to `settings`, to send only with analytics consent ([consent management](/docs/guides/consent)): a revocation then calls `client.disable()` and a grant `client.enable()`. Events still waiting in the batch at a revocation are dropped by the disabled client and still count as delivered, with no ERROR line and no failed count.
