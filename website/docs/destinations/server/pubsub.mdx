# Google Pub/Sub

<PackageLink env="server" github="packages/server/destinations/gcp" npm="@walkeros/server-destination-gcp" />

Server-side event publishing to [Google Cloud Pub/Sub](https://cloud.google.com/pubsub) topics. Each event is serialized as JSON, optionally keyed for per-message ordering, and published via the official `@google-cloud/pubsub` SDK. Supports Application Default Credentials, service account JSON, or pre-configured client injection. Per-rule topic, ordering-key, and attribute overrides. Idempotent topic provisioning with EU storage policy by default.

The destination ships inside `@walkeros/server-destination-gcp` alongside BigQuery; install the package once and import `destinationPubSub` for Pub/Sub.

## Authentication

Three modes. The first one that is set wins:

1. **Pre-configured client.** Pass an existing `PubSub` SDK instance as `settings.client`. Useful for shared clients across destinations or custom transport configuration.
2. **Service account JSON.** Pass credentials via `config.credentials`, either as a parsed object or a JSON string (the destination JSON-parses strings). Back it with a `$secret` whose value is the key file's JSON: `"credentials": "$secret.PUBSUB_SA_KEY"`. If the secret is unset, the flow stops at startup; a string that is not a service account key makes the destination fail to start with `Invalid credentials JSON`. An unset `$env` reference without a default leaves `config.credentials` empty instead: the destination then authenticates with Application Default Credentials, possibly as another identity, and nothing reports it.
3. **Application Default Credentials (ADC).** Nothing to configure beyond `projectId`. Works on GCP-native runtimes (Cloud Run, Cloud Functions, GKE, GCE) where the runtime service account is attached, and locally with `gcloud auth application-default login`.

When `settings.projectId` and the credentials' `project_id` both resolve, the top-level `settings.projectId` wins. The runtime publish target stays unambiguous.

## Ordering

`orderingKey` is a `Mapping.Value` resolved per event. Any resolved value except `undefined`, `null` or an empty string becomes the ordering key as a string, so `false` becomes `"false"`. The topic handle is then constructed with `messageOrdering: true`, and the key goes on the publish.

```json
{
  "settings": {
    "projectId": "my-project",
    "topic": "user-events",
    "orderingKey": "user.id"
  }
}
```

Per-rule overrides live under `mapping.<entity>.<action>.settings.orderingKey`.

If a publish fails for an ordered key, the Pub/Sub client fails every later publish with that key until `topic.resumePublishing(key)` is called. The destination handles this automatically: on publish failure for an ordered key it calls `resumePublishing` immediately; the push still fails, with the SDK's error as its cause.

## Attributes

`settings.attributes` is a `Mapping.Map` of attribute name to mapping value. Each value is resolved per event and stringified. Per-rule overrides under `mapping.<entity>.<action>.settings.attributes` are merged onto the defaults.

```json
{
  "settings": {
    "projectId": "my-project",
    "topic": "events",
    "attributes": {
      "tenant": "user.tenant_id",
      "schema_version": { "value": "v4" }
    }
  }
}
```

## Setup

Provision the topic once per environment:

<CodeSnippet
  code={`walkeros setup destination.pubsub`}
  language="bash"
/>

Setup runs only when `config.setup` is `true` or an object; without it the command provisions nothing and prints `[destination:pubsub] setup: skipped destination.pubsub (config.setup is unset)`. The command is idempotent: re-running it on an existing topic runs drift detection (with `--verbose` it also prints `setup: topic exists`). Drift on `messageStoragePolicy.allowedPersistenceRegions`, `messageRetentionDuration`, `kmsKeyName`, or `labels` logs `[destination:<id>] setup.drift {...}` (a warning line) and never auto-mutates. Migrations are an operator decision.

`config.setup`:

- omitted or `false` (default): no provisioning; the command skips.
- `true`: provisions with safe defaults (EU multi-region storage policy).
- `{ messageStoragePolicy, messageRetentionDuration, kmsKeyName, labels }`: object form for explicit overrides.

Default storage regions: `['europe-west1', 'europe-west3', 'europe-west4']` (EU multi-region). Override `messageStoragePolicy.allowedPersistenceRegions` for projects with org policies that restrict geography.

The provisioning identity needs `pubsub.topics.create` and `pubsub.topics.get` on the project. The runtime publish identity needs `roles/pubsub.publisher` on the topic itself.

Subscription provisioning is owned by the [Pub/Sub source](/docs/sources/server/pubsub), not this destination.

## Emulator

The official Pub/Sub emulator runs locally for development:

<CodeSnippet
  code={`gcloud beta emulators pubsub start --host-port=localhost:8085
export PUBSUB_EMULATOR_HOST=localhost:8085`}
  language="bash"
/>

The SDK automatically picks up `PUBSUB_EMULATOR_HOST`. For explicit configuration, set `settings.apiEndpoint` (e.g. `localhost:8085`).

## Troubleshooting

- **`NOT_FOUND` on publish**: the topic does not exist. Set `config.setup: true` and run `walkeros setup destination.<id>` once. The message names the topic and the project.
- **`PERMISSION_DENIED` / `UNAUTHENTICATED`**: the runtime service account lacks `roles/pubsub.publisher` on the topic, or ADC is not configured. The message names the topic and the role to grant.
- **Ordering stuck**: a previous publish for an ordering key failed. The destination calls `resumePublishing` automatically; if stalls persist, check publish-side error logs for the original failure.
