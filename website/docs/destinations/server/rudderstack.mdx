# RudderStack

<PackageLink env="server" github="packages/server/destinations/rudderstack" npm="@walkeros/server-destination-rudderstack" status="beta" />

Server-side event delivery to [RudderStack](https://rudderstack.com/) via the official [`@rudderstack/rudder-sdk-node`](https://www.npmjs.com/package/@rudderstack/rudder-sdk-node) SDK. Sends the Segment Spec calls `track`, `identify`, `group`, `page`, `screen`, and `alias`, skips an `identify` or `group` call that repeats the previous one, and flushes on shutdown with `flush()`.

## Identity

Identity is resolved from each event: `userId` defaults to `user.id` and `anonymousId` defaults to `user.session`. Override these paths in settings to match your event structure. An event where neither resolves is not sent and fails with `missing-input`.

An `identify` or `group` call is sent only when its `userId` (for a group, its `groupId`) or its traits differ from the previous call of that kind this destination sent. The `anonymousId` and, for a group, the user are not compared. When a second visitor without a `userId` has the same traits, or a second user joins the same group with the same traits, no `identify` or `group` call is sent for them and nothing reports it. Their `track` calls still go out.

## Batching and delivery

This destination batches by default: `config.batch` sends a batch at 20 events, 10 seconds after the last event, or 30 seconds after the first, whichever comes first, and each event keeps its own outcome. Set `config.batch: { size: 1 }` to send each event at once. How batching, retries, deduplication and acknowledgement work for the server SDK destinations is described in [Server SDK destinations](/docs/destinations#server-sdk-destinations).

## Consent

The quickstart sets no `config.consent`, so RudderStack receives every event. Add `config.consent` to send only with consent ([consent management](/docs/guides/consent)).

## Alias support

Unlike the Segment destination, this destination also sends `alias()` calls, to link an anonymous identity to the user id after signup or login. Map `previousId` in a rule's `settings.alias`, as the Alias user example above does. The event needs a `userId` as well: an alias call without one fails the event with `transport`.
