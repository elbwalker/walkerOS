# Segment

<PackageLink env="server" github="packages/server/destinations/segment" npm="@walkeros/server-destination-segment" />

Server-side event delivery to [Segment](https://segment.com/) via the official [`@segment/analytics-node`](https://www.npmjs.com/package/@segment/analytics-node) SDK. Implements the full Segment Spec surface (`track`, `identify`, `group`, `page`, and `screen`) with automatic identity deduplication and graceful shutdown via `closeAndFlush()`.

Identity is resolved automatically from each event: `userId` defaults to `user.id` and `anonymousId` defaults to `user.session`. At least one must be present for a call to be sent. Override these paths in settings to match your event structure.

## Batching and delivery

This destination batches by default: events are collected and sent together once
`config.batch` reaches 15 events or 10 seconds, whichever comes
first. Each event keeps its own outcome, so a failed delivery fails that event
and lands in the dead-letter queue instead of counting as delivered. Set
`config.batch: { size: 1 }` to send each event at once; there is no JSON switch
that turns the default batch off.

A batched event answers `queued` with the reason `batch`. A server source
acknowledges the producer when the event is queued, and a failed flush is
reported (one ERROR line with the status, the failed counter, the dead-letter
queue) but not redelivered. Options are in
[Batch scheduling](/docs/mapping/rule#batch-scheduling).

An event without `userId` or `anonymousId` fails with `missing-input`.
