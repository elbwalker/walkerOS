[d8a](https://d8a.tech/) is a GA4-compatible, warehouse-native analytics
platform. The destination sends walkerOS events to the d8a web tracker using the
GA4 gtag-style `d8a()` API, so existing GA4 mappings translate directly.

## Event Mapping

By default, walkerOS event names are converted to snake_case and sent with the
configured property ID as `send_to`. Override the name and shape per event the
same way you would for GA4:

<CodeSnippet
  code={`mapping: {
  order: {
    complete: {
      name: 'purchase',
      data: {
        map: {
          transaction_id: 'data.id',
          value: 'data.value',
          currency: { key: 'data.currency', value: 'EUR' },
        },
      },
    },
  },
}`}
  language="typescript"
/>

This produces:

<CodeSnippet
  code={`d8a('event', 'purchase', {
  transaction_id: '0rd3r1d',
  value: 462,
  currency: 'EUR',
  send_to: '80e1d6d0-560d-419f-ac2a-fe9281e93386',
});`}
  language="typescript"
/>

## Page views

d8a sends a `page_view` itself when the tracker starts. A walkerOS
`page view` event (the browser source sends one by default) arrives as a
second `page_view`, so each page counts twice. Set `send_page_view: false`, or
ignore the walkerOS event with a rule (`page: { view: { ignore: true } }`).

## Consent Mode

The destination supports d8a's gtag-compatible consent mode. By default,
walkerOS consent keys map to d8a consent fields:

| walkerOS consent key | d8a consent fields                                 |
| -------------------- | -------------------------------------------------- |
| `marketing`          | `ad_storage`, `ad_user_data`, `ad_personalization` |
| `analytics`          | `analytics_storage`                                |

The first consent command sets every mapped field to `denied` before it
applies the update. A walkerOS consent key the mapping does not name changes
nothing. When several keys map to the same field, the field is `granted` only
if every one of them is granted in the current consent state. A mapping of your
own replaces the default, like
`como: { statistics: 'analytics_storage', marketing: ['ad_storage', 'ad_user_data', 'ad_personalization'] }`.
Disable consent mode with `como: false`.

Until the first consent command, d8a counts consent as granted. Without
`config.consent`, as in the installation example, the page view d8a sends when
the tracker starts goes out as granted, and the `_d8a` cookies are set before a
later denial and stay after it. With `config.consent`, such as
`{ analytics: true }`, the collector holds the destination until that consent
is granted (see [consent management](/docs/guides/consent)), so the tracker
starts and sends its page view only after the grant.
