# Google Analytics 4 (GA4)

<PackageLink
  env="web"
  github="packages/web/destinations/gtag"
  npm="@walkeros/web-destination-gtag"
/>

[Google Analytics 4 (GA4)](https://support.google.com/analytics/answer/10089681)
is configured within the unified gtag destination. With `loadScript: true`
walkerOS loads gtag.js and forwards mapped events to GA4.

## Installation

<CodeSnippet
  code={`npm install @walkeros/web-destination-gtag`}
  language="bash"
/>

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationGtag } from '@walkeros/web-destination-gtag';

await startFlow({
  destinations: {
    ga4: {
      code: destinationGtag,
      config: {
        loadScript: true,
        settings: {
          ga4: {
            measurementId: 'G-XXXXXXXXXX',
          },
        },
      },
    },
  },
});`}
  language="typescript"
/>

`loadScript: true` makes walkerOS add gtag.js to the page. Without it walkerOS
injects no gtag.js and only queues its calls in `dataLayer`, so events reach
GA4 only if your page loads gtag.js itself.

This snippet sets no consent, so `config`, and with it Google's own
`page_view`, goes out before any Consent Mode default. Add
`consent: { analytics: true }` to `config`, next to `settings`, before you go
live (see [Google Consent Mode](/docs/guides/consent#google-consent-mode)).

## Let a tag manager own the configuration

If a container (for example GTM) already configures your measurement ID, set
`init: false`. walkerOS then skips the gtag bootstrap entirely, no `js`, no
`config`, no script load, and only sends events, routed by `send_to`, plus its
Consent Mode commands while `como` is on.

<CodeSnippet
  code={`settings: {
  ga4: {
    measurementId: 'G-XXXXXXXX',
    init: false,
  },
}`}
  language="typescript"
/>

The container's own `config` then stays the only one on the page. The settings
walkerOS would put into `config` or use to load the script
(`server_container_url`, `transport_url`, `pageview`, `scriptSrc`) have no
effect with `init: false`: set them on the container's tag. The Consent Mode
default has to come from the page as well, set by your CMP or inside the
container. With `config.consent`, walkerOS sends its denied default and its
updates only after the container's `config`.

## Serve gtag.js first-party

By default gtag.js loads from `googletagmanager.com`. To serve it from your own
tagging server instead, set `scriptSrc` to the
[tag serving path](https://developers.google.com/tag-platform/tag-manager/server-side/dependency-serving)
configured in your server container. walkerOS loads that URL as it is, without
adding the measurement ID.

<CodeSnippet
  code={`settings: {
  ga4: {
    measurementId: 'G-XXXXXXXXXX',
    scriptSrc: 'https://example.com/metrics/tag_serving_path/',
    server_container_url: 'https://example.com/metrics',
  },
}`}
  language="typescript"
/>

`server_container_url` goes into gtag's `config` and does not change where the
script loads from: without `scriptSrc`, gtag.js still loads from
`googletagmanager.com`. If `scriptSrc` fails to load, walkerOS falls back to
`googletagmanager.com`, so measurement keeps working when the container is
misconfigured.

## A page view needs no mapping

The gtag destination snake-cases an `entity action` event name into a GA4 event
name automatically, so `page view` arrives in GA4 as `page_view` with no mapping
at all. An unmapped `product add` would arrive as `product_add` carrying only
`send_to`, which is why the ecommerce event below needs an explicit mapping.

gtag also sends a `page_view` of its own when `config` runs. With the default
settings a pushed `page view` therefore reaches GA4 in addition to that
automatic one, and the page is counted twice. Set `pageview: false` on the
`ga4` settings to keep only the walkerOS event; gtag still adds the page
location and title to it. On a single-page app, also turn off *Page changes
based on browser history events* in the web stream's enhanced measurement
settings: gtag.js still sends those page views with `pageview: false`.

<CodeSnippet
  code={`settings: {
  ga4: {
    measurementId: 'G-XXXXXXXXXX',
    pageview: false,
  },
}`}
  language="typescript"
/>

## Add the ecommerce mapping

Nest the mapping under the gtag destination to turn a `product add` event into
the GA4 `add_to_cart` event. The product price becomes the GA4 `value`, the
currency falls back to `EUR`, and the product is shaped into a GA4 `items` array
via a `this` loop.

<CodeSnippet
  code={`mapping: {
  product: {
    add: {
      name: 'add_to_cart',
      data: {
        map: {
          value: 'data.price',
          currency: { value: 'EUR', key: 'data.currency' },
          items: {
            loop: [
              'this',
              {
                map: {
                  item_id: 'data.id',
                  item_name: 'data.name',
                  quantity: { value: 1, key: 'data.quantity' },
                },
              },
            ],
          },
        },
      },
    },
  },
}`}
  language="typescript"
/>

Pushing a `product add` event:

<CodeSnippet
  code={`elb({
  name: 'product add',
  data: { id: 'ers', name: 'Everyday Ruck Snack', price: 420 },
});`}
  language="typescript"
/>

produces the GA4 `add_to_cart` event:

<CodeSnippet
  code={`gtag('event', 'add_to_cart', {
  value: 420,
  currency: 'EUR',
  items: [{ item_id: 'ers', item_name: 'Everyday Ruck Snack', quantity: 1 }],
  send_to: 'G-XXXXXXXXXX',
});`}
  language="typescript"
/>

## Parameter names

Before sending, the destination replaces every run of characters other than
letters, digits and underscores in a parameter name with one underscore; a
hyphen is the most common case. Tagging `creative-type` under `include: ['data']` produces the
parameter `data_creative-type`, which is sent as `data_creative_type`. Case is
left alone.

Event names are never rewritten this way. `snakeCase` lowercases the event name
and replaces its spaces with underscores; set it to `false` and the name is sent
exactly as configured.

Two parameters are dropped rather than renamed:

| Parameter         | Produced by `include` from |
| ----------------- | -------------------------- |
| `source_platform` | `event.source.platform`    |
| `user_id`         | `event.user.id`            |

Required ecommerce parameters such as `currency`, `value` and `transaction_id`
are unaffected. To keep the platform value, map it to a name of your own:

<CodeSnippet
  code={`data: { map: { platform: 'source.platform' } }`}
  language="typescript"
/>

## Verify in GA4

In GA4, open Admin > Data collection and modification > Data streams, click your
web stream and copy its Measurement ID. Watch Reports > Realtime to confirm the
`page_view` event.

DebugView lists only events sent in debug mode, so while you test, add
`debug: true` to `settings.ga4`: the destination then adds `debug_mode: true` to
every event. Open Admin > Data display > DebugView to inspect the `add_to_cart`
event and its parameters as they arrive, and remove `debug` before going live.
