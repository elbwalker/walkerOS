# Google Tag Manager (GTM)

<PackageLink
  env="web"
  github="packages/web/destinations/gtag"
  npm="@walkeros/web-destination-gtag"
/>

[Google Tag Manager (GTM)](https://tagmanager.google.com/) is a tool to manage
and add third-party integrations to your website, configured within the
unified gtag destination.

To get events into GTM without a flow, use
[walker.js](/docs/getting-started/quickstart/walkerjs): one script tag that
pushes every tagged event to the dataLayer, with a complete
[GTM setup](/docs/getting-started/quickstart/walkerjs#use-it-in-gtm).

## Installation

<CodeSnippet
  code={`npm install @walkeros/web-destination-gtag`}
  language="bash"
/>

<CodeSnippet
  code={`import { startFlow } from '@walkeros/collector';
import { destinationGtag } from '@walkeros/web-destination-gtag';

await startFlow({
  destinations: {
    gtag: {
      code: destinationGtag,
      config: {
        loadScript: true, // walkerOS installs the container; omit it when GTM is already on the page
        settings: {
          gtm: {
            containerId: 'GTM-XXXXXXX',
            dataLayer: 'dataLayer',
          },
        },
      },
    },
  },
});`}
  language="typescript"
/>

Set `loadScript: true` when walkerOS should install the container for you. It
loads `gtm.js` and pushes the `gtm.js` start event into the dataLayer, which is
what Google's own snippet does.

Leave `loadScript` unset when the container is already on the page, for example
when you are feeding an existing GTM setup while you migrate. walkerOS then
neither loads the container nor pushes the `gtm.js` bootstrap event: it adopts
the configured dataLayer (creating it if it does not exist yet) and pushes your
events into it, so your existing triggers keep firing exactly as often
as before.

Each push carries `event` with the event name. With a data mapping (`data` or
`include` on the rule or the destination config, or `settings.gtm.data`), it
carries the mapped values. Without one, it carries the whole walkerOS event as
it is.

`loadScript` is set once per destination and applies to every flavor configured
on it. On a destination that also configures `ga4` or `ads`, the same flag
governs whether those scripts are loaded too.

Consent Mode reaches the container only when the destination declares a consent
signal. With `loadScript: true`:

- With `consent: { marketing: true }` in `config`, walkerOS pushes the denied
  `consent default` before `gtm.js`, loads the container once that consent is
  granted and pushes a `consent update` on every change.
- With `como_advanced` instead, the denied default goes out before `gtm.js` as
  the flow starts, the container and the events go out without waiting, and a
  `consent update` follows every change.
- With neither, consent commands push nothing into the dataLayer and the
  container loads as the flow starts.

A container that is already on the page loads before walkerOS starts, so its
Consent Mode default has to come from the page, set by your CMP or inside the
container. walkerOS's own default, when it sends one, arrives after the
container has started.

## dataLayer example

A mapped event is pushed to the dataLayer with `event` set to the mapped name
and the mapped values beside it. When `settings` configures GA4 and GTM, both
receive every event the destination gets; a rule cannot leave one of them out.
