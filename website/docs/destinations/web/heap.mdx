# Heap

<PackageLink
  env="web"

  status="beta"
/>

[Heap](https://www.heap.io/) (now part of Contentsquare) is a product
analytics platform with auto-capture and retroactive event definitions.
With `loadScript: true`, this destination loads the Heap script from Heap's
CDN. It forwards walkerOS events through `heap.track(name, properties)`, plus
identity, user properties, persistent event properties, and runtime consent.

:::caution
`loadScript: true` loads the classic Heap SDK
(`https://cdn.heapanalytics.com/js/heap-<appId>.js`). That SDK does not replay
the calls the destination queues before it finishes loading, so events pushed
earlier (such as the first page view) do not reach Heap. It also ignores
`disablePageviewAutocapture`, `disableSessionReplay`, and `ingestServer`, and
has no `startTracking()` or `stopTracking()`, so any consent command after it
has loaded stops all further Heap events (see Consent).
:::

## Consent

With `config.consent` declared, the destination is not loaded before the
required consent keys are granted (see
[consent management](/docs/guides/consent)). On each consent command it calls
`heap.startTracking()` when all required keys are granted and
`heap.stopTracking()` otherwise.

The classic SDK that `loadScript: true` loads has neither method. The grant
that loads Heap works, but once the script has loaded, every later
`walker consent` command, even one that repeats the current state, makes the
destination's `on('consent')` handler fail. The collector logs
`on callback failed` and holds the destination's events in its queue, so Heap
receives nothing for the rest of the page view, while `elb` still returns
`ok`. A revocation also does not stop Heap's own capture. This setup keeps
sending events only when your consent source sends no further consent command
after the grant that loads Heap.

<CodeSnippet
  code={`destinations: {
  heap: {
    code: destinationHeap,
    config: {
      loadScript: true,
      consent: { analytics: true },
      settings: { appId: 'YOUR_HEAP_APP_ID' },
    },
  },
}`}
  language="typescript"
/>
