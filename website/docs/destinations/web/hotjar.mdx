# Hotjar

<PackageLink
  env="web"
  github="packages/web/destinations/hotjar"
  npm="@walkeros/web-destination-hotjar"
  status="beta"
/>

[Hotjar](https://www.hotjar.com/) provides session recordings, heatmaps, and
on-page feedback for web products. This destination forwards walkerOS events to
Hotjar via the official
[`@hotjar/browser`](https://www.npmjs.com/package/@hotjar/browser) SDK,
translating events into `Hotjar.event(...)` calls and handling identity and
SPA state changes.

## Consent

The Hotjar SDK has no consent API. Consent is gated at the walkerOS level via
`config.consent`:

<CodeSnippet
  code={`destinations: {
  hotjar: {
    code: destinationHotjar,
    config: {
      consent: { marketing: true },
      settings: { siteId: 1234567 },
    },
  },
}`}
  language="typescript"
/>

Until a listed consent state is granted, the destination does not load Hotjar
and the collector holds its events in a queue. They are sent once consent is
granted, see [consent management](/docs/guides/consent). After a revocation, no
further events reach Hotjar, but the Hotjar script loaded before stays on the
page until the next page load.
