# Meta Pixel

[Meta Pixel (formerly Facebook Pixel)](https://developers.facebook.com/docs/meta-pixel/)
tracks visitor activity and conversions for Facebook and Instagram advertising
campaigns. The destination sends events to the Meta Pixel through its `fbq`
function. Install the destination; mapping events to Meta's format is
optional. An event without a rule goes out with `fbq('track', ...)` under its
walkerOS name, such as `product add`; only `page view` is renamed, to
`PageView`. With `loadScript: true`, as in the quickstart, walkerOS also loads
the Pixel script.

## Installation

<Quickstart data={data} />

The quickstart above sets no consent, so the Meta Pixel loads and receives
every event without `marketing` consent, and a revocation changes nothing. Add
`consent: { marketing: true }` to `config`, next to `settings`, before you go
live: the Pixel then loads once `marketing` is granted, and events pushed
before the grant wait in the queue and are sent then (see
[consent](/docs/guides/consent#gate-a-destination-with-consent)).

## Custom events

Set `trackCustom` in a rule's `settings` to send an event that is not one of Meta's standard events. The destination then calls `fbq('trackCustom', name, params, { eventID })` instead of `fbq('track', ...)`; the `eventID` is the walkerOS event ID, which the Conversions API matches, together with the event name, to deduplicate.

<StepExample example={data.examples.step.customEventWithTrackCustom} />

A destination with `config.consent` calls `fbq('consent', 'revoke')` when the
required consent is revoked and `fbq('consent', 'grant')` when it is granted. A
blocked `fbevents.js` fails later events visibly, and a missing `pixelId` is a
`config` error. A rule with `silent: true` sends no event. A rule whose `data`
resolves to something other than an object is sent with empty parameters, and
its push answers `done`.
