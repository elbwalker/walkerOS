# Mixpanel

<PackageLink

[Mixpanel](https://mixpanel.com/) is a product analytics platform with people
profiles, group analytics, and cohort-based reporting. This destination forwards
walkerOS events to Mixpanel via the official
[`mixpanel-browser`](https://www.npmjs.com/package/mixpanel-browser) SDK,
translating events into `mixpanel.track(...)` calls and resolving identity,
people properties, group assignments, and consent opt-in/opt-out.

## Installation

<Quickstart data={data} />

The quickstart above sets no consent, so Mixpanel starts and receives every
event without `analytics` consent, and a revocation changes nothing. Add
`consent: { analytics: true }` to `config`, next to `settings`, before you go
live (see [gate a destination](/docs/guides/consent#gate-a-destination-with-consent)).

Without `api_host`, the SDK sends to Mixpanel's default host
(`https://api-js.mixpanel.com`); for a project with EU data residency, set
`api_host: 'https://api-eu.mixpanel.com'` in `settings`.

## Intentionally not supported

These Mixpanel methods have no setting in this destination:

- **`alias()`**: in a project with Mixpanel ID Merge, `mixpanel.identify`
  (called through the `identify` setting) connects events from before and
  after login. Without ID Merge, Mixpanel uses `alias()` for this.
- **`register()` / super properties**: set `include` in the destination
  config (next to `settings`, for example `include: ['globals']`) to attach
  event sections to every event instead.
- **`people.track_charge`**: deprecated in `mixpanel-browser` and has no
  effect. Send revenue events as regular `track()` calls with a `revenue`
  property.
- **`time_event` / page view auto-tracking**: walkerOS sources handle event
  capture and timing.

All other built-in `mixpanel-browser` config options pass through `settings`
directly (e.g. `api_host`, `persistence`, `cross_subdomain_cookie`,
`secure_cookie`, `ip`, `property_blacklist`, `loaded` callback, etc.).
