# Optimizely

<PackageLink
  env="web"

  status="beta"
/>

[Optimizely Feature Experimentation](https://www.optimizely.com/products/experiment/feature-experimentation/)
runs A/B tests and feature rollouts. This destination forwards walkerOS events
to Optimizely as conversion events via the official
[`@optimizely/optimizely-sdk`](https://www.npmjs.com/package/@optimizely/optimizely-sdk)
v6 modular API, calling `userContext.trackEvent(eventKey, eventTags)` with
optional revenue/value tags and user attributes.

## Installation

<Quickstart data={data} />

The quickstart above sets no consent, so the Optimizely client starts and
receives every event without `analytics` consent, and a revocation changes
nothing. Add `consent: { analytics: true }` to `config`, next to `settings`,
before you go live (see [gate a destination](/docs/guides/consent#gate-a-destination-with-consent)).

## User ID

Every event needs a user ID, so `settings.userId` is required: without it the
destination does not start and fails with a `config` error. An event where
`settings.userId` resolves to nothing fails with `missing-input` (the push result lists the destination under
`failed` and the collector writes an ERROR line). With `userId: 'user.id'`,
that is every event of an anonymous visitor. To send those events too, give a
fallback chain such as `userId: ['user.id', 'user.device']`; the
[session source](/docs/sources/web/session) sets `user.device` in storage mode.

## Event key

The event key sent to Optimizely is the walkerOS event name, or the rule's
`name` (see the **Mapped event key** example). The rule setting `eventKey` has
no effect: use `name`.

## Revenue

Optimizely expects revenue as an **integer in cents** (e.g. `7281` =
`$72.81`). The destination passes the resolved value through without
conversion. The caller must provide cents. A `revenue` or `value` that does not
resolve to a number, such as the string `"7281"`, is left out.

## Consent

With `config.consent`, the collector holds the destination's events in a queue
until a required consent key is granted, see
[consent management](/docs/guides/consent). The destination's Optimizely client
sends only the events walkerOS tracks, so a revocation needs no vendor call: the
client keeps running, and new events wait for the next grant.

## Feature flags / decide()

This destination does not expose `decide()`, by design. Experiment decisions
belong in application code, where the UI branches; this package covers
outbound conversion tracking.
