# Pinterest Tag

<PackageLink
  env="web"
  github="packages/web/destinations/pinterest"
  npm="@walkeros/web-destination-pinterest"
/>

The [Pinterest Tag](https://help.pinterest.com/en/business/article/install-the-pinterest-tag)
forwards browser conversions to Pinterest Ads Manager for ad optimization,
retargeting, and audience building. This destination wraps the standard
Pinterest Tag snippet (loaded from `s.pinimg.com/ct/core.js`); there is no npm
SDK for the browser tag. Mapped events become
`window.pintrk('track', eventName, { ..., event_id })` calls, with optional
`pintrk('set', ...)` for enhanced matching.

The destination loads `core.js` unless `loadScript` is `false`, and walkerOS
injects it once per page. If your page already has the Pinterest base code, set
`loadScript: false`, or the tag loads twice; the destination still calls
`pintrk('load', tagId)` and, unless `settings.pageview` is `false`,
`pintrk('page')`.

## Standard event taxonomy

Pinterest expects lowercase concatenated event names. The destination does not
translate event names, so every conversion event needs an explicit
`mapping.name`. An event without a rule is sent under its walkerOS name, which
is no Pinterest standard event (`pintrk('track', 'product view', { event_id })`).
To send only the events you map, add a wildcard rule with `ignore: true`
(`'*': { '*': { ignore: true } }`).

| walkerOS event   | Pinterest event | Notes                                                                              |
| ---------------- | --------------- | ---------------------------------------------------------------------------------- |
| `page view`      | `pagevisit`     | Separate from the base code's `pintrk('page')` call the destination makes on init. |
| `product view`   | `viewcontent`   | Single product. `value`, `currency`, and the product in a one-item `line_items` array. |
| `product add`    | `addtocart`     | Single product. Product fields (`product_id`, `product_name`, ...) go in `line_items`. |
| `order complete` | `checkout`      | Multi-product. Use `mapping.data.line_items.loop` to iterate `event.nested`.       |
| `site search`    | `search`        | Use `search_query` field.                                                          |
| `user login`     | `lead`          | Optional `lead_type`. Combine with `settings.identify` for enhanced matching.      |
| `user signup`    | `signup`        | Same identify pattern as `lead`.                                                   |
| (custom)         | `custom`        | Send Pinterest's `custom` event for non-standard conversions.                      |

## Enhanced matching

Pinterest's web tag accepts two enhanced matching fields:

| Field         | Source                              | Notes                                                                               |
| ------------- | ----------------------------------- | ----------------------------------------------------------------------------------- |
| `em`          | `data.email` / `user.email` / etc.  | Plain or hashed. The Pinterest tag hashes a plain email with SHA-256 in the browser. |
| `external_id` | `data.id` / `user.id`               | Stable user identifier, sent as resolved.                                           |

The destination sends only these two fields. CAPI-only fields (`ph`,
`fn`, `ln`, `address`, `country`, `ip`, `ua`) belong to the
[server destination](/docs/destinations/server/pinterest) and are
intentionally not accepted here.

Identity is diffed against the destination's runtime state, and `pintrk('set',
...)` fires only when the resolved identity changes. The
destination-level `settings.identify` is resolved lazily on the first event
(init has no event to bind to), so `pintrk('load', tagId)` is called without
an identity object.

## Consent

Pinterest is an advertising platform. The walkerOS consent key is
**`marketing`** (not `analytics`):

<CodeSnippet
  code={`config: {
  consent: { marketing: true },
  loadScript: true,
  settings: { apiKey: '2612345678901' },
}`}
  language="typescript"
/>

Until `marketing` is granted, the destination does not load the Pinterest Tag
and the collector holds its events in a queue. They are sent once consent is
granted, see [consent management](/docs/guides/consent). Pinterest has no
consent call, so after a revocation walkerOS holds new events again until the
next grant, while the loaded tag stays in the page.

:::note Auto page view
The destination fires `pintrk('page')` once on init by default to match
Pinterest's base code convention. Set `settings.pageview: false` to leave it
out.
:::

## Conversions API {#future-conversions-api}

The [server Pinterest destination](/docs/destinations/server/pinterest) sends
conversions through the Conversions API. Both destinations send the event's
`id` as `event_id`; give an event the same Pinterest event name on both sides
so Pinterest can deduplicate it.
