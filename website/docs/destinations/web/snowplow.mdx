# Snowplow

<PackageLink
  env="web"
  github="packages/web/destinations/snowplow"
  npm="@walkeros/web-destination-snowplow"
/>

[Snowplow](https://snowplow.io/) is a behavioral data platform for collecting
and routing event data. The destination sends events via the browser tracker,
supporting both the npm `@snowplow/browser-tracker` and the JavaScript tracker
(`sp.js`). walkerOS handles tracker initialization, plugin loading, activity
tracking (page pings), and self-describing ecommerce events with context
entities.

## Installation

<CodeSnippet
  code={`npm install @walkeros/web-destination-snowplow`}
  language="bash"
/>

The destination supports two tracking approaches:

- **JavaScript tag (sp.js)**: loads the Snowplow tracker script from CDN
- **npm packages**: uses `@snowplow/browser-tracker` for smaller bundles and tree-shaking

Uses imported functions directly: smaller bundles through tree-shaking, and
type-safe calls.

**Available packages and functions:**

| Package | Functions | Purpose |
|---------|-----------|---------|
| `@snowplow/browser-tracker` | `newTracker`, `trackSelfDescribingEvent` | Core tracking (required) |
| `@snowplow/browser-tracker` | `trackPageView` | `trackPageView` and `pageViewEvent` |
| `@snowplow/browser-tracker` | `trackStructEvent` | Rules with `struct` |
| `@snowplow/browser-tracker` | `setUserId` | `userId` |
| `@snowplow/browser-tracker` | `enableActivityTracking`, `disableActivityTracking` | `activityTracking`; without `disableActivityTracking` a consent revocation fails with `consent-not-applied` |
| `@snowplow/browser-tracker` | `addPlugin`, `addGlobalContexts` | `plugins`, `globalContexts` |
| `@snowplow/browser-plugin-snowplow-ecommerce` | `SnowplowEcommercePlugin`, `setPageType` | Ecommerce tracking, `page` |

Pass every function your settings and rules use: a call whose function is
missing is skipped and the event still counts as delivered (a `struct` rule
without `trackStructEvent` sends nothing). A plugin in
`plugins` is added with `addPlugin`; give a plugin factory a `config` (an empty
object when it takes none), because without one the destination adds the
factory itself and the plugin never starts. The destination cannot call a
plugin's enable function, such as `enableLinkClickTracking`, in this mode:
call it yourself, or use sp.js with a URL plugin. A plugin you enable yourself
keeps sending after a consent revocation until you disable it. Consent tracking
(`settings.consent`) and the runtime privacy controls below work only with
sp.js.

`settings.collectorUrl` is required and the settings schema is closed, so `walkeros validate` rejects a key Snowplow does not read. The Snowplow script is injected once per script URL; if it fails to load, later events fail visibly. If your page already loads sp.js, leave `loadScript` off, or the script loads twice.

Every event needs a rule: its `name` is the action type of the self-describing
event (like `add_to_cart` for the ecommerce action schema). An event that no
rule maps, and that is not the `pageViewEvent`, fails with `missing-input`; add
an `ignore: true` rule for events you do not send.

## User identity and privacy

### Cross-session user stitching

Use `userId` to link events across sessions when users log in. The ID is set
once via Snowplow's `setUserId()` on the first event where the value resolves:

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  userId: 'user.id',
}`}
  language="typescript"
/>

The `userId` setting supports walkerOS mapping syntax:

- `'user.id'` from walkerOS user object (recommended)
- `'globals.user_id'` from globals

### Anonymous tracking

Enable anonymous tracking for privacy-focused collection or before consent:

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  anonymousTracking: {
    withServerAnonymisation: true,
    withSessionTracking: true,
  },
}`}
  language="typescript"
/>

### Runtime privacy controls

Control tracking modes at runtime using exported utility functions. They call
the sp.js tracker (`window.snowplow`) and do nothing with `settings.tracker`;
there, call the browser tracker's own functions of the same name:

<CodeSnippet
  code={`import {
  clearUserData,
  enableAnonymousTracking,
  disableAnonymousTracking,
} from '@walkeros/web-destination-snowplow';

clearUserData();
enableAnonymousTracking({ withServerAnonymisation: true });
disableAnonymousTracking();`}
  language="typescript"
/>

### Consent revocation

On a revocation of the destination's required consent (`config.consent`),
activity tracking and the sp.js URL plugins for link, form, button and YouTube
tracking are switched off, and a grant switches them back on. The error
tracking and FocalMeter URL plugins have no off switch, so a revocation with
them enabled fails visibly (`consent-not-applied`). With `settings.tracker`,
only `activityTracking` follows consent: a plugin you enable yourself keeps
sending after a revocation until you disable it.

### Consent tracking

Track GDPR/CCPA consent events using Snowplow's [Enhanced Consent plugin](https://docs.snowplow.io/docs/collecting-data/collecting-from-own-applications/javascript-trackers/web-tracker/tracking-events/consent-gdpr/).
With `settings.consent`, the destination reacts to walkerOS consent commands and
calls the matching Snowplow consent method. This works with sp.js only: with
`settings.tracker`, no consent event is sent.

**Prerequisites:** load the Enhanced Consent plugin via the `plugins` setting
or include it in your Snowplow script bundle.

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  consent: {
    required: ['analytics', 'marketing'],
    basisForProcessing: 'consent',
    consentUrl: 'https://example.com/privacy',
    consentVersion: '2.0',
    domainsApplied: ['example.com'],
    gdprApplies: true,
  },
}`}
  language="typescript"
/>

| Option | Type | Description |
|--------|------|-------------|
| `required` | `string[]` | walkerOS consent groups to check |
| `basisForProcessing` | `string` | GDPR basis: `consent`, `contract`, `legal_obligation`, `vital_interests`, `public_task`, `legitimate_interests` |
| `consentUrl` | `string` | Privacy policy URL |
| `consentVersion` | `string` | Policy version |
| `domainsApplied` | `string[]` | Domains where consent applies |
| `gdprApplies` | `boolean` | Whether GDPR applies |

The destination decides on the keys of each consent command. A required scope
the command does not name counts as not granted, so a command that only revokes
`marketing` sends `trackConsentDeny` for `analytics` too:

| Required scopes in the consent command | Snowplow method |
|------------------------|-----------------|
| All granted | `trackConsentAllow` |
| None granted | `trackConsentDeny` |
| Some granted | `trackConsentSelected` |

## Media tracking

Track video and audio playback events using Snowplow's [media tracking schemas](https://docs.snowplow.io/docs/collecting-data/collecting-from-own-applications/javascript-trackers/web-tracker/tracking-events/media/).
Each media event is a self-describing event with the media schema as its
`actionSchema`. Like every other event, it needs a rule with a `name`; the
event data comes from the rule's `settings.data`.

### Basic usage

<CodeSnippet
  code={`await elb({
  name: 'video play',
  data: {
    id: 'video-123',
    title: 'Product Demo',
    currentTime: 0,
    duration: 120,
  },
});

await elb({
  name: 'video progress',
  data: { id: 'video-123', percentProgress: 25 },
});

await elb({
  name: 'video pause',
  data: { id: 'video-123', currentTime: 45 },
});

await elb({
  name: 'video end',
  data: { id: 'video-123', duration: 120 },
});`}
  language="typescript"
/>

### Media mapping configuration

Configure media event mappings with the `MEDIA_SCHEMAS` constants. The
`MEDIA_PLAYER` entity (`media_player` 1-0-0) requires `currentTime`,
`duration`, `ended`, `loop`, `muted`, `paused`, `playbackRate` and `volume`:

<CodeSnippet
  code={`import { MEDIA_SCHEMAS } from '@walkeros/web-destination-snowplow';

{
  video: {
    play: {
      name: 'play',
      settings: {
        snowplow: { actionSchema: MEDIA_SCHEMAS.PLAY },
        context: [{
          schema: MEDIA_SCHEMAS.MEDIA_PLAYER,
          data: {
            currentTime: 'data.currentTime',
            duration: 'data.duration',
            ended: { value: false },
            loop: { value: false },
            muted: { key: 'data.muted', value: false },
            paused: { value: false },
            playbackRate: { key: 'data.playbackRate', value: 1 },
            volume: { key: 'data.volume', value: 100 },
          },
        }],
      },
    },
    progress: {
      name: 'percent_progress',
      settings: {
        snowplow: { actionSchema: MEDIA_SCHEMAS.PERCENT_PROGRESS },
        data: { map: { percentProgress: 'data.percentProgress' } },
      },
    },
    pause: {
      name: 'pause',
      settings: { snowplow: { actionSchema: MEDIA_SCHEMAS.PAUSE } },
    },
    end: {
      name: 'end',
      settings: { snowplow: { actionSchema: MEDIA_SCHEMAS.END } },
    },
  },
}`}
  language="typescript"
/>

### Ad tracking

Track video advertisements with pre-roll, mid-roll, and post-roll events:

<CodeSnippet
  code={`import { MEDIA_SCHEMAS } from '@walkeros/web-destination-snowplow';

{
  ad: {
    break_start: {
      name: 'ad_break_start',
      settings: {
        snowplow: { actionSchema: MEDIA_SCHEMAS.AD_BREAK_START },
        context: [{
          schema: MEDIA_SCHEMAS.AD_BREAK,
          data: {
            breakId: 'data.breakId',
            breakType: 'data.breakType',
            startTime: 'data.startTime',
          },
        }],
      },
    },
    start: {
      name: 'ad_start',
      settings: {
        snowplow: { actionSchema: MEDIA_SCHEMAS.AD_START },
        context: [{
          schema: MEDIA_SCHEMAS.AD,
          data: {
            adId: 'data.adId',
            name: 'data.name',
            duration: 'data.duration',
          },
        }],
      },
    },
  },
}`}
  language="typescript"
/>

### Available media schemas

| Schema | Description | Use case |
|--------|-------------|----------|
| `PLAY` | Playback started | Video/audio play |
| `PAUSE` | Playback paused | User pauses content |
| `END` | Playback ended | Video/audio completed |
| `SEEK_START` / `SEEK_END` | User seeking | Scrubbing timeline |
| `BUFFER_START` / `BUFFER_END` | Buffering state | Loading content |
| `QUALITY_CHANGE` | Video quality changed | Adaptive streaming |
| `FULLSCREEN_CHANGE` | Fullscreen toggled | User interaction |
| `VOLUME_CHANGE` | Volume changed | User adjustment |
| `PERCENT_PROGRESS` | Progress milestone | 25%, 50%, 75% markers |
| `ERROR` | Playback error | Error tracking |
| `AD_BREAK_START` / `AD_BREAK_END` | Ad break | Pre/mid/post-roll |
| `AD_START` / `AD_COMPLETE` / `AD_SKIP` | Individual ad | Ad impressions |

### Activity tracking (page pings)

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  activityTracking: {
    minimumVisitLength: 10,
    heartbeatDelay: 30,
  },
}`}
  language="typescript"
/>

### Page view tracking

Snowplow's native `trackPageView()` can be triggered either on init or via a
walkerOS event. Both options require explicit configuration. If neither
`trackPageView` nor `pageViewEvent` is set, no automatic page view tracking
occurs.

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  trackPageView: true,
}`}
  language="typescript"
/>

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  pageViewEvent: 'page view',
}`}
  language="typescript"
/>

### Plugins

Load Snowplow plugins for automatic tracking. The destination supports both
URL-based plugins (sp.js) and npm BrowserPlugin instances. URL plugins need
sp.js: with `settings.tracker`, a URL plugin fails `init` with a `config`
error.

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  plugins: [
    {
      url: 'https://cdn.jsdelivr.net/npm/@snowplow/browser-plugin-link-click-tracking@latest/dist/index.umd.min.js',
      name: ['snowplowLinkClickTracking', 'LinkClickTrackingPlugin'],
      options: { trackContent: true },
    },
  ],
}`}
  language="typescript"
/>

The enable method is derived automatically from the plugin name
(`LinkClickTrackingPlugin` becomes `enableLinkClickTracking`). Override with
`enableMethod` if needed.

### Global contexts

Attach context entities to all events. Supports static objects and dynamic
generator functions:

<CodeSnippet
  code={`{
  collectorUrl: 'https://collector.example.com',
  globalContexts: [
    {
      schema: 'iglu:com.example/app_info/jsonschema/1-0-0',
      data: { version: '1.0.0', environment: 'production' },
    },
    () => ({
      schema: 'iglu:com.example/consent/jsonschema/1-0-0',
      data: {
        advertising: document.cookie.includes('ads_consent=1'),
      },
    }),
  ],
}`}
  language="typescript"
/>
