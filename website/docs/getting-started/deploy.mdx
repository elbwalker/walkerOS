# Deploy

You have a working flow. Every path below runs on infrastructure you control;
managed hosting is the optional alternative at the end.

## From config to running flow

Every self-hosted path is the same two steps, with checks before them:

1. **Validate** the config: `walkeros validate flow.json`
2. **Simulate** an event through it locally, destinations mocked, see
   [bundled mode](/docs/getting-started/modes/bundled#see-your-event)
3. **Bundle** it into an artifact: `walkeros bundle flow.json -o dist/`
4. **Run** the artifact: `runneros start dist/flow.mjs`

Building and running are two tools. `walkeros` (the CLI) validates,
simulates and bundles. `runneros` (the runtime) only starts a prebuilt
artifact: it has no bundler, so a production host never needs a package
manager or registry access. See the [runtime](/docs/apps/runtime) for why the
stages are kept apart.

## Build once

<CodeSnippet code={`npx @walkeros/cli bundle flow.json -o dist/`} language="bash" />

A server flow builds to a **directory**, `dist/` holding `flow.mjs`,
`package.json` and `node_modules/`. Always ship the whole directory. A web
flow builds to a single `dist/walker.js` that any static host can serve.

## Run it yourself

**Docker**, the standard path. Mount the directory where the image expects it:

<CodeSnippet
  code={`docker run -d -p 8080:8080 \\
  -v "$PWD/dist:/app/flow:ro" \\
  walkeros/flow:<version>`}
  language="bash"
/>

Use a `walkeros/flow` version that ships `runneros`, ideally the same version
as the CLI that built the artifact, see [image tags](/docs/apps/runtime#image-tags).
For a self-contained image, use the
[canonical Dockerfile](/docs/apps/runtime#canonical-dockerfile).

**Node**, without Docker:

<CodeSnippet
  code={`npx --package=@walkeros/runner runneros start dist/flow.mjs`}
  language="bash"
/>

Integrated mode needs none of this: the flow deploys with your application and
needs nothing extra. See [integrated mode](/docs/getting-started/modes/integrated).

The same `flow.json` drives every path, so switching between them (or between
providers) is a rebuild and a redeploy, not a migration. To change a running
flow, bundle again and redeploy the new artifact.

## Before production

- Test offline: run the event through the built flow with each destination
  mocked, see [bundled mode](/docs/getting-started/modes/bundled#see-your-event).
- Gate CI: `walkeros validate flow.json --strict` turns contract violations
  into errors, see [validate](/docs/getting-started/flow/validate).
- Wire consent before real traffic, see the [consent guide](/docs/guides/consent).
- Keep `flow.json` in git: deploys stay reviewable and reversible.

## Managed hosting
