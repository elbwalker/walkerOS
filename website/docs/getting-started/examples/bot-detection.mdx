# Bot detection

This server flow scores every incoming event for bot and AI-agent traffic before it reaches your destinations. The Express source forwards the request headers, the bot transformer reads them, and a demo destination logs the annotated events. Nothing is dropped: scoring is annotation, and you filter downstream.

<CodeSnippet
  code={`{
  "version": 4,
  "flows": {
    "default": {
      "config": {
        "platform": "server",
        "bundle": {
          "packages": {
            "@walkeros/collector": { "version": "^4" },

            "@walkeros/destination-demo": { "version": "^4" }
          }
        }
      },
      "sources": {
        "express": {
          "package": "@walkeros/server-source-express",
          "next": "bot",
          "config": {
            "ingest": {
              "map": {
                "userAgent": { "key": "headers.user-agent" },
                "acceptLanguage": { "key": "headers.accept-language" },
                "acceptEncoding": { "key": "headers.accept-encoding" },
                "secFetchSite": { "key": "headers.sec-fetch-site" },
                "secFetchMode": { "key": "headers.sec-fetch-mode" },
                "secFetchDest": { "key": "headers.sec-fetch-dest" },

                "method": { "key": "method" }

            }
          }
        }
      },
      "transformers": {

## Run it

Save the config as `flow.json` and run the bot transformer of the built flow on an event. `--ingest` passes the request context the Express source extracts, here the user agent of a GPTBot request. Nothing is sent anywhere:

<CodeSnippet
  code={`npx walkeros push flow.json -e '{"name":"page view"}' --simulate transformer.bot \\
  --ingest '{"userAgent":"Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko; compatible; GPTBot/1.2; +https://openai.com/gptbot)"}'`}
  language="bash"
/>

You should see, besides an `Output:` line naming the built bundle before each `Simulating` line:

<CodeSnippet
  code={`Simulating transformer: bot
success: true
  transformer.bot
    event {"name":"page view","user":{"botScore":90,"botCategory":"ai-crawler","botProduct":"GPTBot"}}
  Duration: 15758ms`}
  language="bash"
/>

## What you get

Every event now carries `user.botScore` (0-99, higher means more automated), `user.botCategory` (what kind of client it is) and `user.botProduct` when a named detector matched. The reason codes land on `ingest.bot.reasons`, off the analytics event. When the flow runs, the demo destination logs each annotated event under its `name` setting; a request from GPTBot looks like this:

<CodeSnippet
  code={`[Event Logger] {
  "name": "page view",
  "user": {
    "botScore": 90,
    "botCategory": "ai-crawler",
    "botProduct": "GPTBot"
  },
  ...
}`}
  language="bash"
/>

Without `--ingest`, a simulated event has no request behind it, so it resolves no signals at all and scores `null` with category `unknown`, which means not measured rather than human. To act on the scores, filter downstream: for example, a mapping rule on a vendor destination with a `condition` on `user.botScore` and `ignore: true` keeps events scoring above 50 from that vendor. See [Bot detection](/docs/transformers/bot) for the full filtering recipes.
