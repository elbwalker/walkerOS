# Fingerprint to BigQuery

This server flow turns raw request signals into a privacy-friendly identifier before events reach BigQuery. The Express source extracts the client IP and user agent, the fingerprint transformer hashes them into `user.hash`, and the GCP destination writes the events to a table. The ingest keys must be `ip` and `userAgent`, the fingerprint's default inputs (`ingest.ip`, `ingest.userAgent`); the transformer anonymizes the IP, reduces the user agent and keys the hash with a secret salt.

<CodeSnippet
  code={`{
  "version": 4,
  "flows": {
    "default": {
      "config": {
        "platform": "server",
        "bundle": {
          "packages": {
            "@walkeros/collector": { "version": "^4" },
            "@walkeros/server-source-express": { "version": "^4" },
            "@walkeros/server-transformer-fingerprint": { "version": "^4" },
            "@walkeros/server-destination-gcp": { "version": "^4" }
          }
        }
      },
      "sources": {
        "express": {
          "package": "@walkeros/server-source-express",
          "next": "fingerprint",
          "config": {
            "settings": { "port": 8080 },
            "ingest": {
              "map": {
                "ip": { "key": "ip" },
                "userAgent": { "key": "headers.user-agent" }
              }
            }
          }
        }
      },
      "transformers": {
        "fingerprint": {
          "package": "@walkeros/server-transformer-fingerprint",
          "config": {
            "settings": { "salt": "$env.FINGERPRINT_SALT", "length": 16 }
          }
        }
      },
      "destinations": {
        "bigquery": {
          "package": "@walkeros/server-destination-gcp",
          "import": "destinationBigQuery",
          "config": {
            "settings": {
              "projectId": "my-analytics-project",
              "datasetId": "events",
              "tableId": "raw_events"
            }
          }
        }
      },
      "collector": { "run": true }
    }
  }
}`}
  language="json"
/>

## Run it

Save the config as `flow.json` and push an event through the built flow with the destination mocked. The salt comes from the environment. Nothing is written to BigQuery:

<CodeSnippet
  code={`FINGERPRINT_SALT=change-me npx walkeros push flow.json -e '{"name":"page view"}' --simulate destination.bigquery`}
  language="bash"
/>

You should see:

<CodeSnippet
  code={`success: true
  Duration: 42ms`}
  language="bash"
/>

## What you get

In production every event lands as one row in your table, using the standard walkerOS schema (name, entity, action, timestamp, user, and more). The destination receives an `appendRows` call, and the `user` column carries the hash in place of a raw IP or user agent (from the package's examples):

<CodeSnippet
  code={`['appendRows', [{
  "name": "page view",
  "entity": "page",
  "action": "view",
  "user": "{\\"hash\\":\\"158f99cc06e33fd6\\"}",
  ...
}]]`}
  language="bash"
/>

The hash rotates daily by default, so a visitor is not tracked across days. Use a long random salt per deployment in production.
