# Deploy walkerOS to Bunny Magic Containers

This guide deploys a walkerOS event collector to [Bunny Magic Containers](https://bunny.net/magic-containers/), forwarding events to BigQuery. We use GitHub Container Registry (GHCR) to store the Docker image privately.

## Prerequisites

- [GitHub account](https://github.com/) (for private container registry)
- [Bunny.net account](https://bunny.net/) with Magic Containers access
- [Docker](https://docs.docker.com/get-docker/) installed
- [Node.js 22.12+](https://nodejs.org/) installed

## 1. Set Up BigQuery

Follow the [GCP BigQuery setup](/docs/destinations/server/gcp#gcp-setup) to:

- Create a service account with write permissions
- [Download a service account key](/docs/destinations/server/gcp#authentication) (`sa-bigquery.json`)

Step 2 creates the dataset and the events table with `walkeros setup`.

:::caution
The key file will be baked into your Docker image. Keep the image in a **private** registry only.
:::

## 2. Bundle the Flow

Install the CLI and bundle the flow into `dist/`:

```bash
npm install -g @walkeros/cli

# Bundle the flow
walkeros bundle https://www.walkeros.io/flows/gcp-bigquery.json -o dist/
```

This creates `dist/flow.mjs`, `dist/package.json`, and `dist/node_modules/`. The flow reads `GCP_PROJECT_ID` (required), `BQ_DATASET` and `BQ_TABLE` (optional, defaults `walkerOS` and `events`) from the environment when the container starts, so nothing is baked in at bundle time. Only web flows bake `$env` values in, from `config.bundle.env`.

The flow's `"setup"` lets [`walkeros setup`](/docs/destinations/server/gcp#setup-lifecycle) create the dataset and the events table, in the region `BQ_LOCATION` names (default `EU`). Run it once. It finds Google credentials the way the runtime does, from `GOOGLE_APPLICATION_CREDENTIALS` (the key from step 1) or your gcloud application default credentials, and the account needs the setup permissions listed under [Create service accounts](/docs/destinations/server/gcp#create-service-accounts):

```bash
export GCP_PROJECT_ID="your-project-id"
export GOOGLE_APPLICATION_CREDENTIALS="$(pwd)/sa-bigquery.json"
walkeros setup destination.bigquery -c https://www.walkeros.io/flows/gcp-bigquery.json
```

:::tip[Quick Local Test]
Test your flow before building Docker using `push --simulate`. The BigQuery call is mocked, so no credentials are needed:

```bash
export GCP_PROJECT_ID="your-project-id"
walkeros push https://www.walkeros.io/flows/gcp-bigquery.json \
  -e '{"name": "page view", "data": {}}' --simulate destination.bigquery
```
:::

## 3. Build Docker Image

Create a `Dockerfile`:

```dockerfile
FROM walkeros/flow:<version>

# Copy the pre-built flow bundle (flow.mjs, package.json, node_modules/)
COPY dist/ /app/flow/

# Copy service account credentials, owned by the user the image runs as
COPY --chown=walker:walker sa-bigquery.json /app/sa-bigquery.json

# Configure runtime
ENV GOOGLE_APPLICATION_CREDENTIALS=/app/sa-bigquery.json
ENV GCP_PROJECT_ID=your-project-id
```

The image runs as the user `walker` (uid 1001). Without `--chown` the file is
copied as owned by root, so a key that only its owner can read (mode 600) stays
unreadable for that user.

Replace `<version>` with the `walkeros/flow` version matching your CLI (see
[image tags](/docs/apps/runtime#image-tags)). The image already starts
`/app/flow/flow.mjs` on port 8080, so no command or `BUNDLE` is needed. To
bundle inside Docker instead of on your machine, use the
[canonical two-stage Dockerfile](/docs/apps/runtime#canonical-dockerfile).

Build the image with your GitHub Container Registry tag:

```bash
# Replace YOUR_GITHUB_USERNAME with your GitHub username (lowercase)
docker build -t ghcr.io/YOUR_GITHUB_USERNAME/walkeros-collector:latest .
```

## 4. Test Locally

Run the container locally to verify everything works:

```bash
docker run --rm -p 8080:8080 ghcr.io/YOUR_GITHUB_USERNAME/walkeros-collector:latest
```

In another terminal, send a test event:

```bash
curl -X POST http://localhost:8080/collect \
  -H "Content-Type: application/json" \
  -d '{
    "name": "page view",
    "data": {
      "title": "Local Test",
      "path": "/test"
    }
  }'
```

Expected response:

```json
{ "success": true, "timestamp": 1234567890 }
```

The Express source answers a POST [before delivery](/docs/sources/server/express#response-modes-async), so the response says nothing about BigQuery. A failed write shows up as a `Push failed` line in the container log.

Verify in BigQuery:

```bash
bq query --use_legacy_sql=false \
  "SELECT * FROM walkerOS.events ORDER BY timestamp DESC LIMIT 5"
```

## 5. Push to Private GHCR

### Create GitHub Personal Access Token

1. Go to [GitHub Settings → Developer settings → Personal access tokens → Tokens (classic)](https://github.com/settings/tokens)
2. Click **Generate new token (classic)**
3. Name it `ghcr-walkeros`
4. Select scopes:
   - `write:packages` (to push images)
   - `read:packages` (to pull images)
   - `delete:packages` (optional, for cleanup)
5. Click **Generate token**
6. Copy the token (you won't see it again)

### Login and Push

```bash
# Login to GHCR
echo YOUR_GITHUB_TOKEN | docker login ghcr.io -u YOUR_GITHUB_USERNAME --password-stdin

# Push the image
docker push ghcr.io/YOUR_GITHUB_USERNAME/walkeros-collector:latest
```

### Verify Image is Private

1. Go to `https://github.com/YOUR_GITHUB_USERNAME?tab=packages`
2. Find `walkeros-collector`
3. Confirm visibility is **Private** (default for new packages)

:::tip
If the package is public, click **Package settings** → **Change visibility** → **Private**.
:::

## 6. Connect GHCR to Bunny

### Create Read-Only Token for Bunny

For security, create a separate token with read-only access:

1. Go to [GitHub Settings → Personal access tokens](https://github.com/settings/tokens)
2. Generate new token with only `read:packages` scope
3. Name it `bunny-ghcr-readonly`

### Add Registry to Bunny

1. Log in to [bunny.net dashboard](https://dash.bunny.net/)
2. Navigate to **Magic Containers** → **Image Registries**
3. Click **Add Image Registry**
4. As **Registry**, select **GitHub**
5. Enter:
   - **Username**: Your GitHub username
   - **Personal access token**: The read-only token from above
6. Click **Add Image Registry**

## 7. Deploy to Bunny Magic Containers

1. In the bunny.net dashboard, go to **Magic Containers** and click **+ Add App**
2. Search for and select the image `walkeros-collector` from your GitHub
   registry; its `latest` tag is selected automatically
3. Add an endpoint with **+ CDN** (routes HTTP(S) traffic through bunny.net's
   edge network) or **+ Anycast IP** (direct access through an Anycast IP), name
   it `collect` and set the container port to `8080`. Leave **SSL for origin**
   off: the container serves plain HTTP on port 8080
4. Enter the app name `walkeros-collector` and choose a region (the one closest
   to you is preselected)
5. Click **Deploy**
6. Note the endpoint URL (e.g., `https://walkeros-collector-xxxxx.b-cdn.net`)

To run in more regions, add them after the deploy in the app's **Regions and
Scaling** settings.

## 8. Verify Deployment

### Health Check

```bash
curl https://YOUR_BUNNY_ENDPOINT/health
```

### Send Test Event

```bash
curl -X POST https://YOUR_BUNNY_ENDPOINT/collect \
  -H "Content-Type: application/json" \
  -d '{
    "name": "page view",
    "data": {
      "title": "Bunny Production Test",
      "path": "/"
    }
  }'
```

### Query BigQuery

```bash
bq query --use_legacy_sql=false \
  "SELECT name, data, timestamp FROM walkerOS.events ORDER BY timestamp DESC LIMIT 5"
```

## Updating Your Deployment

When you need to update your flow or configuration:

```bash
# 1. Make changes, bundle the flow again and rebuild
walkeros bundle https://www.walkeros.io/flows/gcp-bigquery.json -o dist/
docker build -t ghcr.io/YOUR_GITHUB_USERNAME/walkeros-collector:latest .

# 2. Push new image
docker push ghcr.io/YOUR_GITHUB_USERNAME/walkeros-collector:latest

# 3. In Bunny dashboard: Magic Containers → Your App → Redeploy
```

- Delete the GHCR image from your GitHub packages
- [Clean up BigQuery resources](/docs/destinations/server/gcp#cleanup)
- Delete local files (`dist/`, `sa-bigquery.json`, `Dockerfile`)
