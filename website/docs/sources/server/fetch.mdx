# Fetch

The Fetch source is a Web Standard Fetch API source for walkerOS: a platform-agnostic `(Request) => Response` handler that runs on Cloudflare Workers, Vercel Edge, Deno, Bun, and Node.js 18+. It supports batch processing, configurable CORS, and pixel tracking via a 1x1 transparent GIF for GET requests.

## Responses

| Status | Meaning |
|--------|---------|
| 200 | Event processed, or failed for a reason a resend cannot fix (see below) |
| 400 | Rejected client input: the pipeline declared the event invalid (the body echoes the validation message, for example `Event name is required`), or a batch larger than `maxBatchSize` (default 100) |
| 404 | Path not configured in `paths` |
| 405 | Method not configured on that path |
| 413 | Body larger than `maxRequestSize` (default 102400 bytes) |
| 500 | The pipeline failed to process a valid event for a reason a resend could fix (the body is `Event was not processed`), or an unexpected server fault (`Internal server error`) |
| 207 | Batch request where at least one event was invalid or failed for a reason a resend could fix. The body carries per-index errors |

A failed event is acknowledged or retried by one rule on every server source: see [Producer acknowledgement](/docs/sources/server#producer-acknowledgement).

A per-event "not processed" in a batch logs at DEBUG, because the collector's ERROR line is the signal. A push that throws inside a batch logs an ERROR and answers `Internal server error`.

Invalid input, a body over `maxRequestSize` and a batch over `maxBatchSize` are
counted on `collector.status.sources.<id>.rejected` rather than inflating
`status.failed`. An invalid event is logged at warn with the reason instead of
as an error with a stack trace; an oversized request is logged at debug.

## Ingest metadata

Extract request metadata and forward it through the pipeline.

`config.ingest` must use the `map` operator. Keys are output field names; values are direct field paths on the request scope (no `req.` prefix). A bare object like `{ url: 'url' }` has no operator: `walkeros validate` and the bundle reject it, and if it still runs, the collector logs one ERROR line (`mapping value has no operator`) and no field is extracted.

<CodeSnippet
  code={`const { collector } = await startFlow({
  sources: {
    fetch: {
      code: sourceFetch,
      config: {
        settings: { cors: true },
        ingest: {
          map: {
            userAgent: { key: 'headers.user-agent' },
            origin: { key: 'headers.origin' },
            path: { key: 'path' },
          },
        },
      },
    },
  },
});`}
  language="typescript"
/>

Ingest is opt-in: without `config.ingest` the source forwards no request
metadata. Server destinations with client IP and user agent fields
(Meta, TikTok, Snapchat, Pinterest, Bing, Reddit, Criteo and X (Twitter) conversion APIs, Google Data Manager and Piwik PRO) read `ingest.ip` and `ingest.userAgent` by default, so name the keys
`ip` and `userAgent`. This source has no `ip` path (see below); map it from a
single-value header your own infrastructure sets:

<CodeSnippet
  code={`ingest: {
  map: {
    ip: { key: 'headers.x-client-ip' },
    userAgent: { key: 'headers.user-agent' },
  },
}`}
  language="typescript"
/>

### Available ingest paths

This source builds the shared [request scope](/docs/sources/scope), so every
contract field resolves by key.

| Path | Description |
|------|-------------|
| `method` | Uppercase HTTP method |
| `url` | Absolute request URL |
| `path` | Pathname, no query string |
| `query.<name>` | Query parameter |
| `headers.<name>` | Header, lowercased name |
| `body` | Parsed request body |
| `raw` | The WHATWG `Request` itself |

:::note
`ip` is absent on this source: a Fetch `Request` reports no client IP and
walkerOS does not guess one. Map the header your proxy sets, as in
[Client IP behind a proxy](/docs/sources/server/express#client-ip-behind-a-proxy).
:::

## Usage

### Single event

<CodeSnippet
  code={`fetch('https://your-endpoint.com/collect', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    name: 'page view',
    data: { title: 'Home', path: '/' },
  }),
});`}
  language="javascript"
/>

### Batch events

<CodeSnippet
  code={`fetch('https://your-endpoint.com/collect', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    batch: [
      { name: 'page view', data: { title: 'Home' } },
      { name: 'button click', data: { id: 'cta' } },
    ],
  }),
});`}
