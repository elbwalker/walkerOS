# GCP Cloud Functions

The GCP Cloud Functions source is a runtime adapter for walkerOS whose `push` you assign directly as a Cloud Functions handler. It supports the shared [event envelope](/docs/sources/envelope) including batches, a GET tracking pixel, and configurable CORS. The `@walkeros/server-source-gcp` package also ships [`sourcePubSubPull` and `sourcePubSubPush`](/docs/sources/server/pubsub) for ingesting from Pub/Sub topics; this page covers the Cloud Functions handler only.

## Request format

The event name field is `name`. Every other field of the body is forwarded to
the collector as-is, so `source` (carrying `release` and `trace` provenance)
rides through instead of being dropped.

### Single event

<CodeSnippet
  code={`{
  "name": "page view",
  "data": {
    "title": "Home Page",
    "path": "/"
  }
}`}
  language="json"
/>

### Batch events

Send several events in one request with the shared envelope. See
[Event Envelope](/docs/sources/envelope) for the accepted forms, the
`maxBatchSize` cap and the 207 partial-failure response.

<CodeSnippet
  code={`{
  "batch": [
    { "name": "page view", "data": { "title": "Page 1" } },
    { "name": "button click", "data": { "id": "btn1" } }
  ]
}`}
  language="json"
/>

## Responses

| Status | Meaning |
|--------|---------|
| 200 | Event processed, or failed for a reason a resend cannot fix (see below) |
| 400 | Rejected client input: the pipeline declared the event invalid (the body echoes the validation message, for example `Event name is required`), or a batch larger than `maxBatchSize` |
| 405 | A method other than POST, GET (pixel) and OPTIONS, or GET with `enablePixelTracking: false` |
| 500 | The pipeline failed to process a valid event for a reason a resend could fix (the body is `Event was not processed`), or an unexpected server fault (`Internal server error`) |

A malformed `application/json` body is rejected by the Functions Framework
before the source runs: 400 with an HTML body, no CORS headers, not counted.

A failed event is acknowledged or retried by one rule on every server source: see [Producer acknowledgement](/docs/sources/server#producer-acknowledgement).

Invalid input is counted on `collector.status.sources.<id>.rejected` rather than
inflating `status.failed`, and is logged at warn with the reason instead of as an
error with a stack trace. A batch over `maxBatchSize` is answered 400 and not
counted.

The source sets no body size limit of its own. The Functions Framework accepts
up to 1024mb and leaves the cap to the platform: 32 MB for a 2nd gen HTTP
function, 10 MB for 1st gen.

`settings.timeout` has no effect today: a request whose push takes longer still
waits for it and answers as above.

## Ingest metadata

Extract request metadata and forward it through the pipeline.

`config.ingest` must use the `map` operator. Keys are output field names; values are direct field paths on the request scope (no `req.` prefix). A bare object like `{ ip: 'ip' }` has no operator: `walkeros validate` and the bundle reject it, and if it still runs, the collector logs one ERROR line (`mapping value has no operator`) and no field is extracted.

<CodeSnippet
  code={`const { collector } = await startFlow({
  sources: {
    gcp: {
      code: sourceCloudFunction,
      config: {
        settings: { cors: true },
        ingest: {
          map: {
            // only when your load balancer sets it; otherwise leave ip unmapped
            ip: { key: 'headers.x-client-ip' },
            userAgent: { key: 'headers.user-agent' },
            origin: { key: 'headers.origin' },
          },
        },
      },
    },
  },
});`}
  language="typescript"
/>

### Available ingest paths

| Path | Description |
|------|-------------|
| `ip` | The Functions Framework's `req.ip`. The framework trusts every proxy, so this is the leftmost `X-Forwarded-For` entry, which a client can set itself. For the client IP, map a header your load balancer sets, see [Client IP behind a proxy](/docs/sources/server/express#client-ip-behind-a-proxy) |
| `headers.*` | HTTP headers (user-agent, origin, etc.) |
| `method` | HTTP method |
| `path` | Pathname, no query string |
| `query.*` | Query parameter, repeated keys joined with `,` |
| `url` | Absolute request URL, or `''` when there is no `host` header |
| `body` | Request body: parsed JSON (also a `text/plain` body that is JSON), the raw string for other `text/plain`, the fields of an `application/x-www-form-urlencoded` body, or `undefined` for other content types |
| `raw` | The Functions Framework request itself |

## Pub/Sub

The same `@walkeros/server-source-gcp` package also exports `sourcePubSubPull` (streaming pull subscriber) and `sourcePubSubPush` (HTTP webhook handler) for ingesting events from a Pub/Sub topic. See the [Pub/Sub source page](/docs/sources/server/pubsub) for full settings, lifecycle, decoders, OIDC verification, and setup reference.
