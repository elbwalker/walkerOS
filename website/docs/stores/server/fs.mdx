# Filesystem

<PackageLink env="server" github="packages/server/stores/fs" npm="@walkeros/server-store-fs" />

## Structured vs file mode

The fs store has two modes, decided once at init by `config.file`:

- **Structured (default):** values are structured `StoreValue` data, serialized to and from disk by the shared core codec. Use for session state, lookups, and cached responses.
- **File (`file: true`):** values persist as raw bytes byte-exact. `set()` accepts a `Uint8Array` or `string` and writes it untouched; `get()` hands the exact bytes back. Use for serving assets such as walker.js, where byte fidelity matters.

One store instance is exactly one mode. Set `file: true` on the store declaration to opt into byte-exact serving.

## API

<CodeSnippet
  code={`const file = await store.get('walker.js'); // StoreValue | undefined
await store.set('data.json', { ok: true }); // structured value
await store.set(
  'walker.js',
  new Uint8Array([
    /*…*/
  ]),
); // file mode: raw bytes
await store.delete('old-file.txt'); // void`}
  language="typescript"
/>

In file mode, `get()` returns the bytes as a `Uint8Array` leaf and `set()` rejects non-`Uint8Array`, non-`string` values with a clear error, so served assets stay intact byte-for-byte.

## File serving pattern

Use with the file transformer to serve static assets from the local filesystem. The express source maps the request path into `ingest.path` and runs the transformer in its `next` chain; a transformer that no chain names never runs. Set `file: true` so the store persists and returns bytes byte-exact:

<CodeSnippet
  code={`{
  "stores": {
    "assets": {
      "package": "@walkeros/server-store-fs",
      "config": {
        "settings": { "basePath": "./public" },
        "file": true
      }
    }
  },
  "sources": {
    "http": {
      "package": "@walkeros/server-source-express",
      "config": {
        "settings": { "paths": ["/collect", "/static/*path"] },
        "ingest": { "map": { "path": { "key": "path" } } }
      },
      "next": "file"
    }
  },
  "transformers": {
    "file": {
      "package": "@walkeros/server-transformer-file",
      "config": { "settings": { "prefix": "/static" } },
      "env": { "store": "$store.assets" }
    }
  }
}`}
  language="json"
/>

A GET to `/static/walker.js` answers with `./public/walker.js` from disk; a path the store does not hold gets the source's usual answer (for a GET, the express source's 200 tracking pixel). Omit `file` (or set it false) for a structured key-value store instead.

A relative `basePath` resolves against the working directory of the process. The [runtime](/docs/apps/runtime#file-paths-at-runtime) changes into the bundle's folder before it loads the flow, so there `./public` is the `public` folder next to the bundle; copy it there with `include`, or use an absolute path.

## Security

- **Path traversal protection**: Keys with a `..` segment (`/` or `\` separated) or a leading `/` or `\` are rejected: `get` answers a miss, `set` and `delete` do nothing. Each rejection is a WARN line, which the default log level (`ERROR`) does not show
- **Base path scoping**: All operations are restricted to the configured `basePath` directory
- **Intermediate directories**: `set()` creates parent directories automatically via `mkdir -p`

## When to use

| Scenario | Recommended store |
|----------|-------------------|
| Local development | **Filesystem**: files on disk, no credentials needed |
| Docker with baked-in assets | **Filesystem**: mount or copy files into the image |
| Cloud / managed deployments | [S3](./s3): files in a bucket, hot-swappable |
| Caching / ephemeral data | Built-in [cache tier](../cache.mdx): in-process, no I/O |
