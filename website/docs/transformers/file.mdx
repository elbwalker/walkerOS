# File

<PackageLink
  env="server"
  github="packages/server/transformers/file"
  npm="@walkeros/server-transformer-file"

Serves static files from a [store](/docs/stores) backend. Reads the file by `ingest.path`, derives the Content-Type from the file extension, and responds directly. Returns `false` to stop the transformer chain so no further transformers or destinations run for the request.

The source maps the request path into `ingest.path`, which the transformer reads, and runs the transformer in its `next` chain. `file: true` on the store makes it hand back each file's raw bytes. Without it every read fails with the `decode` code (one ERROR line per cause and minute) and the express source answers a GET with its 200 tracking pixel instead of the file; `walkeros validate` warns about the missing flag.

<Configuration type="transformer" data={data} />

## How it works

1. Reads `ingest.path` from the request context
2. Strips the configured `prefix` (if set), e.g. `/static/image.png` becomes `image.png`
3. Looks up the remaining path in the store via `store.get(key)`
4. If found, derives the Content-Type from the file extension, sets Content-Length for string and Buffer content, and responds with the content
5. Returns `false` to stop the chain. No further transformers or destinations run.
6. If the file is not found or the path doesn't match the prefix, the request goes on unchanged like any other request on the source; for a GET the express source answers with its 200 tracking pixel

## Environment

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `store` | `Store.Instance` | Yes | Store providing file content. Without one, every request passes through with a WARN line, which the default `ERROR` log level does not show, and `walkeros validate` does not report it. |

## Cache and file chain

Put a cache on the source to answer repeated file requests from memory, without reading the store again. A cache on the file transformer itself never stores an entry, because the transformer stops the chain once it responds:

<CodeSnippet
  code={`"stores": {
  "files": {
    "package": "@walkeros/server-store-fs",
    "config": { "settings": { "basePath": "./public" }, "file": true }
  }
},
"sources": {
  "http": {
    "package": "@walkeros/server-source-express",
    "config": {
      "settings": { "paths": ["/collect", "/static/*path"] },
      "ingest": {
        "map": {
          "method": { "key": "method" },
          "path": { "key": "path" }
        }
      }
    },
    "cache": {
      "rules": [
        {
          "match": {
            "and": [
              { "key": "ingest.method", "operator": "eq", "value": "GET" },
              { "key": "ingest.path", "operator": "prefix", "value": "/static" }
            ]
          },
          "key": ["ingest.method", "ingest.path"],
          "ttl": 300
        }
      ]
    },
    "next": [
      {
        "match": { "key": "ingest.method", "operator": "eq", "value": "GET" },
        "next": "file"
      }
    ]
  }
},
"transformers": {
  "file": {
    "package": "@walkeros/server-transformer-file",
    "config": { "settings": { "prefix": "/static" } },
    "env": { "store": "$store.files" }
  }
}`}
  language="json"
/>
